AI safety · data leakage

Would you paste this?

People paste passwords, API keys, Aadhaar and card numbers into chatbots every day, usually without noticing. parda ("veil" in Hindi) spots them before you hit send, swaps each one for a placeholder, and puts the real values back into the chatbot's answer. It runs entirely in your browser.

Measured

How well does it work?

Synthetic test sets

1,200 chat drafts used while building, then 600 written separately and run once (held out). The point is to check every format; real text is the harder test.

vs Microsoft Presidio

Presidio is the standard open-source PII detector. It was given every predefined recognizer, including its India ones, and any overlapping entity counted as a catch. Held-out set:

pardaPresidio

In real chatbot prompts

Every user turn in 2 shards of WildChat-1M and in ShareGPT: 665,413 real messages people sent to ChatGPT. WildChat's authors had already scrubbed PII with Presidio; what's left is what that scrub missed.

Hand-checked precision

A random sample of flags, read one by one. v0.1 was tuned on WildChat and tested on unseen ShareGPT. Its failures were fixed, then v0.2 was tested on a second fresh sample. The v0.2 numbers are the honest ones.

Do chatbots keep the placeholders?

The redact → ask → restore loop only works if the model repeats the placeholder. 160 tasks whose answer must repeat the sensitive values (a table, a message, a JSON object, an .env file), redacted two ways, answered by three local models and Gemini 3.5 Flash-Lite. Tags (parda's default) came back intact more reliably.

Under the hood

How it works, and where it fails

Formats, then proof. Each detector matches a real format (Aadhaar, PAN, GSTIN, IFSC, UPI handles, card numbers, IBAN, plus 15 secret formats from OpenAI, Anthropic, AWS, GitHub, Google, Slack, Telegram and others), then checks it: the Verhoeff checksum for Aadhaar, Luhn for cards, the GSTIN check character, mod-97 for IBANs.
Context decides. The 12 digits after "order", "txn" or "PNR" are not an Aadhaar. A number that's the value of "marketCap": isn't one either. Neither are password = getText() or postgres://user:password@host.
Redact with memory. The same value always gets the same placeholder, so the chatbot's answer still makes sense, and restoring maps each one back. You can choose tags or format-preserving fakes.
One file, everywhere. The demo, the game and the benchmark all import the same parda.js. It scans tens of thousands of messages a second.

Limitations

  • No names or addresses. It finds identifiers with a format. Free-text PII like names needs a language model; add them as private words instead.
  • Indian mobile numbers are noisy on real text. 9 of 24 flags in the hand check were right. Ten-digit codes starting with 6 to 9 are everywhere (tariff codes, SAP IDs, transaction references).
  • It can't tell a real key from a fake one that has the right format. The game's values are generated and never real.
  • The synthetic sets are easy by design and show coverage, not real-world accuracy. Read the hand-checked numbers.
